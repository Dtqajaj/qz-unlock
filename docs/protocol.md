# 协议速查

帧格式：`[2 字节 msgid 大端][protobuf3 body]`

心跳实测：`2a fb` 出 → `2a fc` 回（11003 / 11004），大端确认。

## 登录

```
10000 wc1 {
  e8e=1 string   userId
  cv=2  int32    13（客户端版本，写死）
  w69=3 string   "4399h5"
  xol=4 int32    0
  kv=5  repeated p_order_attr {
    {k:"userId",   v:<userId>,   t:1}
    {k:"userName", v:<userName>, t:1}
    {k:"time",     v:<time>,     t:1}
    {k:"sign",     v:<sign>,     t:1}
  }
}
10001 ubg { code=1 }     ← code=1 成功
```

四个值全来自游戏 iframe URL：
`https://h5game.haowan823.cn/newqz/index_hao.html?userId=…&userName=…&time=…&sign=…`

实测整帧 **130 字节**，字节序列：

```
27 10 0a 06 38 30 33 30 35 36 10 0d 1a 06 34 33 39 39 68 35 20 00
    └┬┘ └────┬────┘ └┬┘ └────┬────┘ └┬┘
     f1   "803056"  f2=13  "4399h5" f4=0
```

**`sign` 不可伪造**：4399 服务端对 `(userId, userName, time)` 签名，过期即拒。
4399 登录接口还有图形验证码，光有账号密码拿不到 sign。

## 写档接口

### 刷枪 22064 nbe

```
nbe { type=1 int32, id=2 int32 }
mvp { code=1 }    // 22065 回包
```

| type | 回包 22024 | 效果 |
|---|---|---|
| **1** | `{id, ztv=1}` 无 vyx | **永久不过期** |
| 0 / 2 | `{id, ztv=1, vyx=now+3600}` | 限时 1 小时 |
| 3~6 | `{id, ztv+1, vyx=…}` | 逐次续命 1 小时 |

服务端**不校验**广告回执、付费、id 是否在售。89 个 eqID 全部 `code=1`。

**注意**：`ztv` 是服务端生成的常量 1，客户端传不进去。
想让它变成 -1（界面显示「永久」）只能客户端改写下行。

### 刷角色 22066 ifm

```
ifm { type=1, id=2 }
dyp { code=1 }    // 22067
```

id 1..7 全部成功，无配额限制。

### 解锁栏位 22015 h3f

```
h3f { id=1, type=2 }
pn4 { code=1 }    // 22016
```

id 0..5 全部 `code=1`，plan1..5 全部 `open=1` 且持久。

### 强化 22020 mev

```
mev { id=1, type=2 }
x7m { code=1 }    // 22021
```

- `type=0` 扣合金升一级
- `type=1`（免广告强化）→ **code=9 拒绝**，不信任客户端

### 广告商店 22052 + 22054

```
n4o { id=1 }      // 22052 买（= 看一次广告）
c4w { code, id, hzb }     // 22053
nlf { id=1 }      // 22054 领
a93 { code, id, hzb, tlr } // 22055
```

**必须成对发**。只发 22052 只把 `hzb` 加一，奖励要到 22054 才到账。

服务端**不校验广告是否真播**。列表在 22051：
```
p_ad_shop { id=1, rvx=2 奖励, nbo=3 需广告次数, hzb=4 已看, fxt=5 上限, tlr=6 已领 }
```

### 钻石商店 22058

```
i6d { id=1 }
d8d { code, id, tlr }
```

需消耗钻石。列表在 22057，`limit=4` 是上限。

## 数据结构

```
p_weapon  { id=1, lv=2, w0l=3, ztv=4, vyx=5 }
p_item    { id=1, ztv=2, vyx=3 }        ← 这里的 ztv 是【数量】
p_role_qz { id=1, ztv=2, vyx=3 }
p_plan    { id=1, open=2, ovg=3, list=4 }
p_id_num  { id=1, ztv=2 }
```

**`p_weapon` 的 field2 是等级，`p_item` 的 field2 是数量。** 混了就会把数量当等级解析。

`ztv = -1`（编码成 10 字节 `ff ff ff ff ff ff ff ff ff 01`）= 永久。

## 频率

| 间隔 | 结果 |
|---|---|
| 500ms | 52 条连发零失败 |
| 200~260ms | 短批次能过，长批次开始丢 |
| 130ms | 大量静默丢弃 |

**丢包无任何报错**：连接还是 OPEN、不抛异常，只有回包 body 变空。

判断被丢：`22065` 回包 body 为空 / `22003` 完全不回 / 连接正常但连续无回包。

风控码：`10001 {code:1013}` = 频率超了，停 30 分钟。
`1014`（`e_code.h1q`）= 真封禁。

## 做不到的

### 服务端存不了 ztv=-1

试过全部失败：

| 尝试 | 结果 |
|---|---|
| `nbe` 加 field4 = -1 | 整条静默丢弃 |
| `mev type=1` | `code=9` |
| 22045 / 22047 / 22049 | `code=5` 不支持 |
| 22030 / 22032 / 22034 | `code=1` 但无变更 |
| **20044 djv {ztv, type}** | **接受任意 ztv 回包，但不落库** |

`20044` 是唯一能传数量的上行（客户端源码 `ry3("djv").Send({ztv:1,type:1})`），
实测发 `{ztv:100}` 回 `{code:1, ztv:100}`，但**不产生任何 22026/11005 变更**。

### 资源数量改不了

74 条 22xxx 上行里**没有一条能设置库存数量**。所有发放接口只传商品 id，
数量由服务端查配置表决定，且每个入口都有 `limit`。

要真写数量需要服务端源码/数据库权限或运营后台鉴权，
那是入侵第三方服务器的范畴，不在协议层能解决的范围内。

## 客户端改写（显示永久）

拦截下行 `22000`：

```js
// 原始：{id:88, ztv:1, vyx:1794538730}   ← 限时
// 改写：{id:88, ztv:-1}                  ← 永久
```

保留 `id` 和 `lv`，`ztv` 强制 -1，`vyx` 丢弃。

**必须防重入**：改写后的帧 `dispatchEvent` 回去会再命中自己的 hook，
实测 44 帧膨胀成 1376 条。用 `WeakSet` 给改写后的 buffer 打标记。
